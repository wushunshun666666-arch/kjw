## 本地预测与数据链路

- 采集入口 → `portal_draw` → 本地算法 → `portal_prediction` → 前台只读接口。前台访问不会采集、生成预测或调用第三方预测接口。
- 算法：`weighted-frequency-v1`，至少 20 期，最多最近 100 期，新到旧赋予 N 至 1 的权重，分别计算大小和单双；并列时取最新类别。组合、杀组使用同一份已保存快照，显示及命中规则沿用参考模板。
- 唯一目标期号，只生成尚未入库的下一期；历史导入、过期、未来时间、样本不足均跳过。预测不可修改或删除，保存算法版本、时间、样本快照、分数和 SHA-256。
- 预测生成时间必须早于开奖结果时间，才展示历史命中情况。启用前没有保存的预测显示 `-`，不补造历史命中。
- 06:32:34 数据库快照：67 期开奖、23 条预测；第一条为 3495354 期，生成于 05:15:56；最新预测为 3495376 期，基于 3495375 期，于 06:31:21 保存，预计开奖 06:34:30。见 [数据库证据](prediction-database.json)。
- 算法是可追溯的历史频率计算，不代表概率估计或命中率保证。

## 本次修复及可配置差异

1. 预测完全改为本地算法和数据库留档，移除第三方预测调用及开关；公开参考网关只允许公告相关路径。
2. 二维码根据后台登录地址生成并嵌入站点图标；修复 PHP 8.4 下旧二维码库的局部弃用提示兼容，不修改第三方库。短地址、1800 字符长参数地址均已使用独立二维码解码器验证一致。超出 2048 字节的登录地址在后台保存时拒绝，避免二维码容量错误。见 [解码结果](qr-decode-results.json)。
3. 联系页原模板将网址当作图片，参考站实际显示破图。本地改为“后台联系图标／站点图标 + 后台联系链接”，主链接为空时使用备用链接；图片已成功加载。见 [修复前对比](contact-before.json)、[修复后图片](local-contact.jpg)。
4. 独立打开数据由来页时，本站顶部域名由初始配置补全；参考站直接打开时域名为空。
5. 上游只返回最近 20 期，本站历史按持续采集积累，不借用参考站 100 期补齐。开奖时间沿用自有接口，可能与参考站相差一分钟。预测自启用后记录，之前显示缺失。
